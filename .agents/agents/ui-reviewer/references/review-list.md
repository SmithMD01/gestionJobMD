# Checklist de revisión UI

## Alcance

- [ ] Se identificaron las rutas revisadas.
- [ ] Se identificaron los archivos modificados.
- [ ] Se revisaron únicamente los componentes relacionados.
- [ ] Se indicó si la revisión fue parcial o completa.

## Sistema visual

- [ ] Se utilizan tokens del proyecto.
- [ ] No existen colores directos innecesarios.
- [ ] Se mantiene la jerarquía entre fondos y superficies.
- [ ] Se respetan tipografías y tamaños existentes.
- [ ] Se respetan espaciados, bordes y sombras.
- [ ] Existe contraste suficiente.

## Componentes

- [ ] Se buscaron componentes existentes.
- [ ] No se crearon duplicaciones innecesarias.
- [ ] Las variantes están justificadas.
- [ ] Los cambios no rompen otros usos.

## Botones

- [ ] La variante corresponde a la acción.
- [ ] El texto es claro.
- [ ] Existen estados hover, focus, disabled y loading.
- [ ] Las acciones destructivas están protegidas.
- [ ] No se utilizan iconos sin etiqueta accesible.

## Tablas

- [ ] Los filtros están ubicados correctamente.
- [ ] Existe paginación.
- [ ] Existe selector de cantidad de filas.
- [ ] Se contemplan estados de carga, vacío y error.
- [ ] Se mantiene el comportamiento responsive.
- [ ] Las acciones respetan los permisos.

## Toasts

- [ ] Se utiliza el componente estándar.
- [ ] El tipo de mensaje es correcto.
- [ ] La animación es consistente.
- [ ] Existe cierre manual.
- [ ] La duración es adecuada.
- [ ] Se respeta el límite de toasts visibles.
- [ ] Se utiliza un rol accesible apropiado.

## Responsive y accesibilidad

- [ ] La vista funciona en pantallas pequeñas.
- [ ] Los elementos se pueden utilizar con teclado.
- [ ] El foco es visible.
- [ ] Los textos son legibles.
- [ ] Los mensajes importantes son anunciados correctamente.
- [ ] Se respeta la reducción de movimiento.
